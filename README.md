JWT middleware\n- Session management across page reloads with NextAuth.js\n\n**Stateless vs Stateful**:\n- Gemini API calls via `generate_content()` are stateless (no memory)\n- Chat sessions via `client.chats.create()` maintain conversation context\n- Database stores full history for session recovery\n\n**Memory Management**:\n- Active chat objects stored in `GeminiService.active_chats`\n- On session reload, history is replayed to rebuild context\n- Leverages Gemini's 1M token context window for long conversations\n\n**Voice Features**:\n- OpenAI Whisper transcribes voice input to text\n- Gemini TTS synthesizes AI responses to speech\n- Audio processing supports MP3, WAV, and other formats\n\n**Multimodal Capabilities**:\n- Images analyzed using Gemini Vision API\n- PDFs extracted with PyPDF2 for text analysis\n- File metadata stored in database for session context\n\n## Hackathon Highlights\n\nBuilt for [Gemini 3 Hackathon](https://gemini3.devpost.com) (Dec 17, 2025 - Feb 9, following files:\n- `railway.json` - Backend deployment configuration\n- `railway.toml` - Multi-service deployment (backend + frontend)\n- `Procfile` - Backend process definition\n- `frontend/Procfile` - Frontend process definition\n- `.github/workflows/ci.yml` - CI/CD pipeline\n\n#### Deploy to Railway\n\n1. **Install Railway CLI**:\n   ```bash\n   npm install -g @railway/cli\n   ```\n\n2. **Login to Railway**:\n   ```bash\n   railway login\n   ```\n\n3. **Initialize Railway project**:\n   ```bash\n   railway init\n   ```\n\n4. **Deploy Backend**:\n   ```bash\n   railway up --service=backend\n   ```\n\n5. **Deploy Frontend** (after backend is deployed):\n   ```bash\n   railway up --service=frontend\n   ```\n\n#### Environment Variables\n\nConfigure the following environment variables in Railway:\n\n**Backend**:\n- `GOOGLE_GEMINI_KEY` - Your Google Gemini API key\n- `OPENAI_API_KEY` - Your OpenAI API key for Whisper\n- `JWT_SECRET` - Your JWT secret token\n- `DATABASE_URL` - SQLite database path (default: `sqlite:///data/mentorai.db`)\n\n**Frontend**:\n- `NEXT_PUBLIC_API_URL` - Backend URL (e.g., `https://your-backend.railway.app`)\n- `NEXTAUTH_SECRET` - Your NextAuth secret\n- `NEXTAUTH_URL` - Frontend URL (e.g., `https://your-frontend.railway.app`)\n\n#### CI/CD Pipeline\n\nThe GitHub Actions workflow automatically:\n- Runs backend tests (`pytest`)\n- Runs frontend tests (`jest`)\n- Runs linting checks\n- Deploys to Railway on merge to `main`/`master` branch\n\nTo enable CI/CD deployment:\n1. Add `RAILWAY_TOKEN` to GitHub repository secrets\n2. Push to `main` or `master` branch\n\n## Development Timeline\n\n- \u2705 Week 1: API integration, database, testing\n- \u2705 Week 2: Auth system, Next.js frontend, dark theme\n- \u2705 Week 3: Voice features, multimodal capabilities\n- \u2705 Week 4: Testing, QA, deployment setup (Railway + CI/CD)\n- \u2705 Week 5: Documentation (API, Setup, Theme), demo prep, presentation\n\n## Contributing\n\nThis is a hackathon project, but feedback welcome!
